# 模块说明

## 顶层入口

### `__init__.py`

KiCad 加载插件时执行。主要职责：

- 将插件根目录加入 `sys.path`。
- 导入 `kicad_dfm.plugin.Plugin`。
- 调用 `Plugin().register()` 注册 ActionPlugin。
- 捕获注册异常并写入 debug 日志。

### `__main__.py`

提供独立 wx 应用启动方式，主要用于非 KiCad 环境或开发调试：

- 定义 `StandAloneApp`。
- 初始化 `wx.Locale`。
- 执行 `_main()` 并进入 `MainLoop()`。

### `kicad_dfm/plugin.py`

KiCad 插件入口类：

- `Plugin.__init__()` 设置插件名称、分类、描述、工具栏图标。
- `Plugin.Run()` 调用主入口 `_main()`。

### `kicad_dfm/_main.py`

单实例启动入口：

- 调用 `SINGLE_PLUGIN.show_existing()`。
- 如果没有已存在窗口，则创建 `BaseApp`。

### `kicad_dfm/_baseApp.py`

wx 运行环境初始化：

- 将 `_` 绑定到 `wx.GetTranslation`。
- 添加语言资源目录。
- 复用 KiCad 当前 `wx.Locale` 加载翻译域。
- 查找 KiCad PCB 编辑器窗口作为父窗口。
- 创建并显示 `DfmMainframe`。

## 主窗口和主面板

### `kicad_dfm/dfm_mainframe.py`

项目核心协调者，负责主窗口、用户动作、流程串联和摘要刷新。

关键职责：

- 获取当前 PCB、文件名、板名、用户单位。
- 初始化摘要数据结构 `json_analysis_map`。
- 处理“快速 DFM 检查”和“综合 DFM 检查”两个显式入口。
- 调用 KiCad 本地分析、Gerber/Drill 导出与本地扫描，并保留远端请求/JSON 解析兼容路径。
- 显示当前分析类目/阶段和确定进度，处理 `Stop Analysis` 的协作式取消请求。
- 维护 `analysis_result` 和 `kicad_result`。
- KiCad 6/7 分析成功后自动同步 UUID-backed 结果到会话临时原生 DRC marker；KiCad 8+ 不启用 native marker。
- 打开详情窗口、孔密度窗口和规则窗口。
- 关闭时恢复 KiCad 层/元素可见状态并删除临时图形。

关键方法：

- `init_data_view()`：初始化摘要表和历史缓存。
- `on_select_native_dfm()`：快速 Native 入口。
- `on_select_combined_dfm()`：Native + Gerber enriched + merge 的综合入口。
- `_run_analysis_entry()`：三个本地/兼容入口共用的启动、取消、异常和进度收尾生命周期。
- `on_select_export_gerber()`：旧综合入口回调的兼容别名；不再绑定主按钮。
- `on_select_gerber_dfm()`：保留的独立 Gerber-enriched 兼容入口；不占用主窗口产品入口。
- `run_offline_analysis()` / `run_combined_analysis()`：分别发布 `kicad_native` 和 `combined` 结果。
- `add_temp_json()`：若项目名匹配，复用本地缓存结果。
- `add_all_item()`：汇总兼容结果和本地补充结果，刷新主表。
- `show_gerber_export_issues()`：综合检查发现 Gerber/Drill/ZIP 交付完整性问题时自动集中展示。
- `create_child_frame()`：创建问题详情窗口。
- `show_rule_manager()`：抽取并展示规则。
- `unit_conversion()`：按 KiCad 用户单位格式化显示。
- `get_current_location()`：通过 ipinfo 判断国家/地区。

### `kicad_dfm/core/progress.py`

统一描述分析进度和取消状态：进度事件携带当前工作内容与完成比例，本地检查和 Gerber/Drill 扫描在安全边界读取停止标志。停止后的不完整结果不会发布到主表或写入分析缓存。

### `kicad_dfm/services/analysis_results.py`

定义统一分析契约和合并编排：

- 稳定模式为 `kicad_native`、`gerber_strict`、`gerber_enriched`、`combined`。
- `AnalysisStageResult` 保存单阶段 legacy 结果、问题、摘要、profile、contract 和来源视图。
- `CombinedAnalysisService` 固定先运行 Native、再运行 Gerber，之后合并 legacy UI 视图、问题列表、摘要和契约。
- `stable_finding_key()` 优先使用 UUID，纯文件结果回退到规则、图层和物理几何；`source_finding_key()` 保留 strict/enriched 的不可变制造证据别名。
- enriched 是 Gerber 最终判定来源；仅存在于 strict、且已被 enrichment 明确抑制的疑似项不会进入综合 verdict。
- 来源视图是 JSON-native 独立快照；Combined 避免对完整树进行第二次无意义规范化。

### `kicad_dfm/services/analysis_cache.py`

原子保存各分析模式最近一次完整结果。缓存身份包含 PCB 绝对路径、输入文件内容摘要、规则组、界面语言和契约版本；PCB、相关 Gerber/Drill、规则、语言或算法版本变化时自动失效。主窗口异步选择最新有效缓存，综合缓存不可用时回退到 Gerber 或 KiCad native 缓存。缓存上限为 128 MiB，结构预检最多遍历 100 万树节点；超限 Combined 跳过持久化但不影响当前 UI，Native 回退缓存仍会保留。未变化输入通过文件状态快速验证，避免每次打开都重新哈希大型制造文件。

### `kicad_dfm/services/board_statistics.py`

计算三个直接展示的板级统计量：钻孔数/板框有效面积得到孔密度；两面阻焊开窗内的焊盘和未盖油过孔铜面积得到沉金面积百分比；有网络且外层可接触的焊盘与未盖油过孔得到飞针点数。统计结果同时供 KiCad 对象分析和 Gerber 导出分析摘要使用。

### `kicad_dfm/dfm_maindialog/`

主窗口内嵌面板和数据模型。

- `ui_dfm_maindialog.py`：由 wxFormBuilder 生成的主面板 UI，包含“快速 DFM 检查”“综合 DFM 检查”、规则按钮、各检查项按钮和摘要列表。
- `dfm_maindialog_view.py`：为摘要列表配置自定义渲染列和响应式按钮布局；文件完整性问题不占用固定摘要行。
- `dfm_maindialog_model.py`：`wx.dataview.DataViewIndexListModel`，将摘要项映射为表格行，并根据颜色控制显示样式。

## 文件导出

### `kicad_dfm/create_file.py`

封装 KiCad 制造文件导出。

- `CreateFile.export_gerber(gerber_dir, layer_count=None)`：
  - 设置 Gerber plot 参数。
  - 清空输出目录。
  - 根据铜层数生成 plot plan。
  - 遍历 plot plan 输出 Gerber 文件。
- `CreateFile.export_drl(gerber_dir)`：
  - 通过 `EXCELLON_WRITER` 生成钻孔和 map 文件。

当前导出层数逻辑覆盖 1、2、4、6 层。其他层数没有显式 plot plan。

### `kicad_dfm/services/export.py`

负责制造文件输出编排：

- `gerber_output_dir(..., include_metadata=True)`：返回 `<PCB目录>/HQDMF`，不可写时返回临时目录 fallback 元数据。
- `export_fabrication_package()`：输出到 `HQDMF/Gerber_<PCB文件名>`，并在 `HQDMF` 下生成 `Gerber_<PCB文件名>.zip`。
- 导出前只清理当前 `Gerber_<PCB文件名>` 子目录，不清理 `HQDMF` 内其它文件。

### `kicad_dfm/services/export_checks.py`

负责本地检查导出的 Gerber/Drill 包，不依赖 KiCad 和网络：

- 检查输出目录、缺文件、空文件、ZIP、铜层数量、钻孔/map、板框文件。
- 支持 KiCad 版本生成的带板名前缀文件名，例如 `video-CuTop.gbr`、`video-EdgeCuts.gbr`。
- 调用 Gerber/Excellon parser 生成 `GerberScan` / `ExcellonScan`。
- 单个 Gerber/Drill parser 异常会记录为阻塞性 `Geometry Parse Error`，并计入 profile 的 `parse_errors`，其它文件继续分析。
- 调用扫描器计算铜间距、焊盘尺寸、孔环、孔到铜、阻焊、SMD 焊盘上孔和铜到板边。
- 将制造能力结果尽量映射到原生检查项；`Gerber Export` 只保留交付完整性问题。
- 文件侧结果会标记 `source`、`confidence` 和 `geometry_basis=gerber_derived`，后续高置信 UUID 回映可继续增强定位。
- 为 Gerber/Drill 文件坐标结果填充 `segment`、`point`、`bbox`、`width`、`diameter` 等 raw 字段，后续归一化为详情窗口可定位坐标。
- `ExportChecks.profile` 记录扫描耗时、看到/解析的文件数、跳过原因、Gerber/Drill 文件数、native result 数、issue finding 数和是否触发上限。
- 原生几何结果不设静默数量上限：所有红色/黄色违规明细均保留并进入详情；黑色正常结果只按子项保留最具代表性的极值，避免正常项占用大量内存。空间索引只排除经包围盒下界证明不可能触发规则的对象，不得截断候选或跳过后续规则。
- `analyze_export_with_results(..., include_profile=True)` 会额外返回 profile；默认三元组返回保持兼容。

### `kicad_dfm/services/result_object_mapper.py`

Gerber/Drill 结果到 KiCad 原生对象的高置信回映服务：

- 输入兼容结果 row、board 和 backend。
- 使用 raw `segment` / `point` / `bbox`，按 Gerber mm 坐标转换为 KiCad nm 坐标。
- 同时检查层名、对象类型、track segment、item bbox；point 几何只在需要中心点兜底时读取对象位置。
- 按 `gerber`、`drill`、`all` 三类缓存候选对象、对象 bbox 和 width，并建立 layer 索引；候选缓存会先按 UUID/identity 在原始 KiCad 对象阶段去重，再读取 layer/bbox/width，避免同一 via 同时来自 track 集合和 via 集合时造成同置信 ambiguous 或重复几何读取；drill 候选只保留 via 和有实际钻孔的 pad，避免 Excellon 点位误映射到无孔 SMD pad；gerber 候选会排除 NPTH pad，避免铜图形回映到非金属化孔外形；批量行映射时避免重复遍历 board 和重复读取候选几何属性，也会在评分前用 bbox 粗筛跳过远同层对象，避免跨层、远距离对象或无关中心点读取进入精算。
- 钻孔结果中的 `Drl` / `Drill` / `Excellon` 属于文件层别名，不作为 KiCad 物理铜层过滤，避免漏掉实际位于 F.Cu/B.Cu/内层的 pad 或 via。
- 只有唯一高置信候选才回填 `id`，并将 `geometry_basis` 提升为 `hit_test`。
- legacy `related_segment` / `related_point` / `related_bbox` 兼容 raw 会独立匹配 related 对象；当缺少 `related_id` / `related_file` 时不会继承主对象 UUID，避免双对象问题定位错绑到同一个 KiCad 对象。
- 低置信、多候选、无几何和已映射状态都会写入 `raw.uuid_mapping`，但不替换原始文件路径 id。

### `kicad_dfm/services/export_gerber_commands.py`

Gerber 命令级解析层，只处理文本命令、单位、坐标和绘制模式，不创建 DFM finding。

主要职责：

- `iter_gerber_commands()`：按 `*` / `*%` 切分命令，支持一行内多个 Gerber 命令。
- 解析 `%MO`、`G70/G71` 单位，`%FS` 坐标格式，`G90/G91` 坐标模式，`G74/G75` 圆弧象限模式。
- 解析 D01/D02/D03、`G01/G02/G03`、`G36/G37`、`G54Dnn`、坐标 X/Y/I/J。
- 解析 `%SR` step repeat，包括大小写命令和内部空格写法。
- 忽略 Gerber 注释和常见属性命令，避免把元数据误判为几何。

### `kicad_dfm/services/export_gerber_apertures.py`

Gerber 光圈和宏解析层，负责把 `%ADD` / `%AM` 转换为可计算的几何 primitive。

主要职责：

- 标准光圈：圆形、矩形、椭圆、正多边形，以及圆/矩形孔。
- 宏光圈：参数替换、变量赋值、基础算术表达式、circle、outline、polygon、center-line、lower-left-line、thermal。
- flash primitive 构造：圆、矩形、椭圆、多边形区域和宏 primitive。
- 共享几何 helper：`offset_point()`、`gerber_flash_kind()` 等由 parser 和兼容模块复用。

### `kicad_dfm/services/export_gerber_primitives.py`

Gerber 几何落库层，负责把 parser 状态机识别到的 draw、flash、region 转换并写入 `GerberScan`。

主要职责：

- `add_gerber_draw()`：按当前插补模式生成线段；线性 draw 直接落库，圆弧 draw 离散为多段。
- `add_gerber_flash()`：根据光圈 primitive 写入铜图形或 clear mask，宏光圈按 primitive 极性拆分。
- `add_region_primitives()`：处理 region 与 step repeat 偏移。
- `add_trace_width_finding()`：为铜层 draw aperture 生成去重后的 `Smallest Trace Width` finding。
- `gerber_segment_bbox()` / `offset_primitive()`：为定位 raw 字段和 step repeat 复用。

### `kicad_dfm/services/export_parsers.py`

Gerber/Excellon 文件扫描状态机。

Gerber 路径：

- `parse_gerber_scan()` 维护单位、坐标格式、当前光圈、插补模式、极性、region、step repeat 等状态。
- draw、flash、region 交给 `export_gerber_primitives.py` 写入 `scan.primitives`、`scan.segments` 和 `scan.clear_masks`。
- 铜层 draw aperture 宽度生成 `Smallest Trace Width` 候选；EdgeCuts 缺 draw 或开口会生成板边相关 finding，开口端点会携带 `raw.primary` / `raw.related` 便于定位到相邻板框对象。

Excellon 路径：

- `parse_excellon_scan()` 解析单位、tool、孔坐标、slot 和孔距。
- 孔径、槽宽、槽长和孔距会生成可映射到原生检查项的 finding，并在 `raw.primary` / `raw.related` 中携带 drill 几何证据用于 UUID 回映。

`export_parsers.py` 仍 re-export 部分 Gerber helper，供 `export_geometry.py` 等旧兼容模块导入；新增代码应优先导入更具体的 `export_gerber_commands.py`、`export_gerber_apertures.py` 或 `export_gerber_primitives.py`。

### `kicad_dfm/services/export_scanners.py`

基于 parser 输出的 primitive 做跨文件 DFM 几何扫描：

- `scan_copper_spacing()`：同铜层可见 primitive 的 trace/pad 间距。
- `scan_pad_size_and_ring()`：Gerber pad 外形较短一边（不扣钻孔）和 PTH 孔环。
- `scan_holes_on_smd_pads()`：孔与 SMD pad 重叠。
- `scan_drill_to_copper()`：PTH/Via 孔到真实走线，以及 NPTH 孔到全部铜对象的距离；NPTH 跨所有铜层寻找全局最近对象，每孔只输出一条 `Drl` 层结果。
- 阻焊扫描：检查阻焊桥、阻焊盖线、阻焊覆盖多个网络和应开窗 SMD pad 的缺失开窗。
- `scan_copper_to_board_edge()`：铜 primitive 到 EdgeCuts 线段距离。
- `scan_hole_to_board_edge()`：Excellon 圆孔/槽孔的孔壁到 EdgeCuts 线段距离，并按 plating、`ViaDrill` 及 PCB 回映语义分类。

扫描器优先使用 bbox/x-index 预筛和安全剪枝；清除极性图形通过 `clear_masks` 影响可见 primitive。`GerberScan` 缓存 clear mask 索引，供可见铜、阻焊、Pad size、RingHole、Holes on SMD Pads 和 Drill-to-Copper 复用。Pad size 只使用 pad 的实际外形短边，不再以钻孔或 clear mask 推导“剩余铜宽”。Drill-to-Copper 中 PTH/Via 候选严格限定为走线 primitive，排除 pad flash 和 zone/region；NPTH 候选包含全部铜层的走线、pad 与铺铜，并在所有可报告候选中只输出每孔的全局最小值。完整覆盖判断对圆形、矩形、slot/obround 使用精确几何或边界采样回退，避免部分开窗被当作完整清除。
Holes on SMD Pads 的文件侧目标只接受 X2 明确标注的 `SMDPad`，不再把未标注的普通 flash 猜成 SMD。孔类型按 Excellon 镀铜属性以及同心的 X2 `ViaPad` / `ComponentPad` 区分为 Via、NPTH、PTH；重叠值使用钻孔中心线到 pad 实际 primitive/多边形的径向压入量，不使用 pad bbox 代替异形铜面。
Copper Spacing 会先按当前最优值和 x 方向距离剪枝，再进入网络、类别、bbox gap 和精确 gap 计算。阻焊开窗、孔到铜、悬空端点、未连接过孔和网络连通分量使用二维 bbox 网格索引查询局部候选；复杂 region 的点包含判断使用按 Y 分桶的边索引，避免大面积铺铜让扫描退化为全量两两精算。耗时扫描循环会回调具体工作项（铜间距、孔到铜、信号完整性、阻焊）并读取停止信号。Copper-to-Board Edge 会对 Edge.Cuts segment 使用 x-window 候选起点，避免每个铜 primitive 都从最左侧板边重新进入精确距离计算。
Pad size、RingHole、Holes on SMD Pads、Drill to Copper、Drill Hole Spacing 等跨文件或双对象结果会在 `raw.primary` / `raw.related` 中携带 pad、drill 或 copper primitive 的精确几何证据，用于 UUID 回映和 related 对象定位。Smallest Trace Width、Hole Size、Copper-to-Board Edge 等单对象文件侧结果也会在 `raw.primary` 中携带对应 Gerber/Drill primitive。

## 远端分析和 JSON 解析

### `kicad_dfm/dfm_analysis.py`

负责上传压缩包、轮询分析结果、下载 JSON，并调用 `core/dfm_json.py` 归一化分析数据。当前 Gerber DFM 按钮不走此路径；该模块作为历史/兼容路径保留。

关键方法：

- `guonei_download_dfm_file()`：国内上传和结果获取流程。
- `haiwai_download_dfm_file()`：海外上传和结果获取流程。
- `api_request_interface()`：执行上传 POST 请求并处理网络异常。
- `guonei_requset_dfm_analysis_file()` / `haiwai_requset_dfm_analysis_file()`：轮询解析结果。
- `download_file()`：流式下载远端 JSON。
- `analysis_json()`：读取远端 JSON，并委托 `dfm_json.parse_file()` 生成兼容结果、问题列表和摘要。

异常处理主要通过 `wx.MessageBox` 提示用户，并可靠结束进度状态；用户也可通过停止按钮请求终止后续检查。

## 本地 KiCad 分析

### `kicad_dfm/services/offline_analysis.py`

离线分析编排入口，创建兼容结果骨架，调用 `LocalChecks`，并生成 `DfmSummary`：

- `IMPLEMENTED_LOCAL_CATEGORIES`：当前 KiCad 对象本地实现的检查项清单。
- `COMPAT_CATEGORIES`：兼容远端 JSON 和本地摘要的检查项清单。
- `LOCAL_CHECKS`：本地检查类别与 `LocalChecks` 方法的声明式执行表。
- `OfflineDfmAnalysis.analyze()`：返回 `analysis_result`、`kicad_result`、`issues`、`summary`、`profile`。
- `profile`：记录 index 构建、每个 category、总耗时、问题数量和结果行数，默认写入 debug 日志。

### `kicad_dfm/core/rule_contract.py`

规则契约一致性校验：

- 校验 `RULE_CATALOG` 的必需字段、空类别和重复子项。
- 校验离线实现类别、兼容类别、主界面摘要项和 KiCad 6/7 native marker 分类是否能对齐。
- 提供统一 `rule_key(category, item)`，供 KiCad 对象结果和 Gerber/Drill 文件侧结果生成稳定规则 key；本地 KiCad 结果会先把翻译后的显示项映射回规则目录原名，避免中文/英文界面生成不同 key。

### `kicad_dfm/services/local_checks.py`

当前 KiCad 对象本地检查主实现。它构建一次 board index，然后复用索引完成线宽/线距、焊盘、孔、板边和 SMD 焊盘上孔等检查。`BoardIndex` 同时缓存按层索引、x-start / 最大 bbox 宽度元数据、扁平 tracks/pads/zones 集合、SMD pads 子集和有铜 pads 子集，铜层集合只由 tracks、有铜 pads 和 zones 推导，避免 NPTH-only 图层污染跨层候选；PTH pad 的铜候选会按已知铜层展开，并在分层索引里使用带候选层名的 `IndexedItem` 副本，展开后重新按 x 起点排序，使详情 `related_layer` 与被检查铜层一致，同时保证 `nearby_items()` 的二分剪枝不会漏候选；铜距/孔到铜等分层规则使用该展开索引，Copper-to-Board Edge 等非层特异规则使用原始有铜 pad 集合，避免结果层被跨层候选污染；SMD 等表贴 pad 仍只在自身层参与铜距检查；`IndexedItem` 缓存对象 UUID、对象类型标记和几何字段，索引构建时会利用 tracks/pads/zones/drawings 来源减少无用类型探测，避免多条规则反复展开分层字典、重复过滤焊盘类型或反复跨后端查询 via/track/pad 类型；内部同对象过滤优先使用 Python identity 并用 UUID 兜底，物理对象 pair 去重使用带类型前缀的 UUID/identity key，避免 KiCad SWIG 不同 wrapper 指向同一底层对象时产生自比较或重复结果，也避免无 UUID 对象与 UUID 对象混合时 key 排序不稳定；`nearby_items()` 会用最大 bbox 宽度回溯窗口，避免起点较早但仍覆盖目标的宽对象被中间小对象隔断而漏检。

主要检查：

- `get_signal_integrity()`：
  - 检查断线、锐角、孤铜、悬空线端和未连接过孔。
  - 悬空线端的连通查询使用端点 geometry candidate 进入同网 x-start 索引，避免长 trace 的整体 bbox 把中段远离端点的对象带入触碰精算。
- `get_line_width()`：
  - 遍历 `PCB_TRACK`。
  - 记录线宽、图层、UUID。
  - 用 `ColorRule` 判定颜色。
- `get_trace_spacing()` / `get_pad_spacing()` / `get_smd_spacing()`：
  - 基于同层对象 bbox 预筛，计算 track-track、track-pad、pad-pad、track-zone、pad-zone、zone-zone 间距。
  - zone 铜对象复用同层 x-start 索引和 bbox-aware 距离，避免普通铜距漏掉铺铜边界；PTH pad 铜环按已知铜层展开为候选，避免内层或背面 trace/pad/zone 与 PTH 铜环的间距漏检。
  - `Smallest Trace Spacing` 保留通用 pad 间距与 BGA 子项；非 BGA 的 SMD-SMD 间距由独立的 `SMD Spacing / SMD Pad Spacing` 检查。跨层展开后的 PTH pad pair 按 UUID 去重；距离均为铜外形边缘到边缘。
  - NetTie 不做全板网络等价：声明组内成员按局部结构处理；外部普通 SMD pad 只有与同网成员共享铜层且直接间隙不超过成员局部 clearance 时，才获得该结构内的局部豁免。
  - trace-pad、pad-zone、pad-pad 铜间距只把有铜 pad 作为候选；NPTH pad 保留在孔到铜和孔类规则中，避免非金属化孔外形误触发铜间距。
- `get_annular_ring()`：
  - 遍历 `PCB_VIA` 和 PTH 焊盘。
  - 计算孔环值。
  - 记录 pad/hole 直径和 UUID。
- `get_hole_diameter()` / `get_drill_hole_spacing()` / `get_drill_to_copper()`：
  - 检查孔径、孔边到孔边和孔边到规定铜对象的距离；孔径类统一归入 `Hole Size`，孔厚径比为板厚/PTH 孔径。
  - 孔对象、孔半径和孔距候选由 `BoardIndex` / `IndexedItem` 缓存；孔距候选使用实际钻孔几何生成 bbox：via 走圆孔半径，pad 钻孔走 drill x/y 外接框，slot/非圆孔距也按孔 bbox 边界计算。长径比按需读取并缓存同一份板厚，避免大焊盘外形 bbox 造成远距离孔对进入精确计算，也避免无 PTH 时读取板级属性或每个 PTH 重复读取板厚。
  - 孔到铜候选使用实际孔 bbox 与规则间距剪枝。PTH/Via 的 `*-to-Trace` 子项只接收同层 track，不接收 pad 或 zone；NPTH-to-Copper 在全部铜层接收 track、有铜 pad 和 zone，最终只保留每孔的全局最小距离并把主结果层设为 `Drl`。圆孔使用圆形距离精算，slot 到 track 使用胶囊体/线段距离；同 UUID 自身铜和跨层重复物理对象会去重。
- `get_pad()`：
  - 遍历封装焊盘。
  - 直接取焊盘外形较短一边，不扣除孔尺寸。
  - 以长边/短边大于 1.2 区分 Long Pads 和 Short Pads。
- `get_copper_to_board_edge()`：
  - 检查走线、铺铜、过孔和焊盘到板框距离。
  - 板边候选预筛使用 `BoardIndex` 缓存的每条 Edge.Cuts segment bbox、x-start 索引和最大 bbox 宽度，不只看整体板框 bbox；后续距离精算也只遍历 x-window / bbox 精筛后的候选 Edge.Cuts segment，因此可覆盖内部槽、开孔和切口附近铜对象，并减少复杂板框下的无关线段计算。
  - SMD 焊盘使用 `SMD-to-Board Edge`，非 SMD 有铜焊盘按通用 `Copper-to-Board Edge` 规则归类；NPTH pad 不作为铜到板边对象，避免非金属化孔外形误报铜距。
- `get_hole_to_board_edge()`：
  - 对 PTH、Via、螺丝孔和普通 NPTH 分别套用独立阈值，距离定义为实际孔壁到最近 Edge.Cuts，而不是焊盘铜外形到板边。
  - 圆孔按半径扣除；旋转槽孔优先使用 KiCad `GetEffectiveHoleShape()` 的精确碰撞距离，兼容后端退化为长圆孔 capsule 计算。
  - 螺丝孔仅由 footprint 名称中的 mounting/screw 语义识别，防止把普通大尺寸 NPTH 误归为螺丝孔。
- `get_special_drill_holes()` / `get_holes_on_smd_pads()`：
  - Special Drill 只检查正/长方形孔和半孔；过孔、PTH、NPTH 与 SMD 焊盘重叠归入独立的 `Holes on SMD Pads` 类别。
  - Special Drill 的 pad 钻孔分支复用 `BoardIndex.holes`，避免无孔 pad 进入半孔/孔形判断；正/长方形孔必须有明确的直角形状证据，不能由非圆枚举或长短轴不相等推断，因此标准 oblong/capsule 槽孔不会误报。半孔判定对 slot/非圆孔使用孔 bbox 到板边线段距离。Holes on SMD Pads 的候选严格来自按层 SMD pad 索引，粗筛使用实际孔 bbox，精算调用 KiCad `GetEffectiveHoleShape()` 与目标 pad 的逐层 `GetEffectiveShape()`；通过缩小钻孔有效形状求径向压入量，因此旋转圆角矩形及 custom pad 的 bbox 空白区域不会报错。PTH/NPTH 分支只接受真实 PTH/NPTH 属性并复用 `BoardIndex.holes`，贯穿孔会检查其跨越的所有铜层且不按网络跳过。
- `get_missing_smask_openings()`：
  - SMD pad 检查复用 `BoardIndex.smd_pads` 子集并读取 pad 阻焊开窗属性；外层铜区通过同侧 F/B.Mask 开窗索引匹配，避免把正常 pad 开窗误报为缺失。
- `get_solder_mask_analysis()`：
  - 分别生成 Solder Mask Bridge、Solder Mask Covers Trace 和 Solder Mask Covers Multiple Nets 结果；多网络检查只使用可靠 net 信息。
- `get_signal_integrity()`：
  - Missing Connections 使用 `BoardIndex` 缓存的按网 connectable 对象。KiCad backend 声明 `connected_item_ids_are_components` 时，一次原生连接查询直接取得完整分量，避免簇内每个对象重复搜索；其它 backend 保留逐节点 BFS 和几何回退。
  - 跨层连通按对象实际连通铜层集合相交判断：PTH pad / through via 可连接所有铜层，盲埋孔复用缓存的 layer pair span，避免把未跨到的内层 trace 误判为已连接。
  - pad/via/track 与 zone 的连通使用实际已填充铜形状；KiCad 后端优先调用原生有效图形碰撞，兼容后端回退到填充多边形距离。PTH 中心即使位于钻孔或热焊盘避空内，只要孔环/热焊盘与内层 zone 接触，仍视为同网连通。
  - NPTH pad 仍参与孔类 DFM 检查，但不会进入 Signal Integrity 的电气连通索引，避免把同网走线误判为通过非金属化孔连接。

这些结果保存在 `DfmMainframe.kicad_result`，详情窗口通过 UUID 直接定位 KiCad 对象。本地 KiCad 对象结果会标记 `source=kicad`、`confidence=1.0` 和 `geometry_basis=exact_kicad`。Gerber/Drill 本地扫描生成的文件坐标结果会进入同一兼容结果结构，并通过临时图形定位。

旧 `kicad_dfm/analysis.py` 过渡包装已移除；主窗口通过 `services/offline_analysis.py` 和 `services/local_checks.py` 统一执行本地分析。

## 详情窗口和定位

### `kicad_dfm/child_frame/dfm_child_frame.py`

问题详情窗口，负责展示、过滤、导航和定位。

主要能力：

- 根据检查项加载结果列表。
- 根据稳定 `rule_key` 读取当前实际规则，在筛选区显示规则值，并在下方以“中英文说明/建议 + 规则示意图”的左右分栏展示规则上下文。
- 支持按层和问题类型筛选。
- 默认过滤 `black` 正常项。
- 选中问题后高亮 KiCad 对象或绘制临时图形。
- 自动聚焦到问题对象。
- 根据选项控制是否隐藏无关层；Gerber/Drill 文件坐标结果不会触发“隐藏全部图层”的定位路径。

关键方法：

- `dispose_result()`：根据组合框过滤正常项。
- `set_layer()`：根据结果图层刷新层列表。
- `set_color_rule()`：生成详情列表显示文本和颜色。
- `analysis_process()`：核心定位逻辑。
- `process_items()` / `set_items_Brightened()`：批量处理匹配对象。
- `get_layer` / `get_type_data` / `get_result`：为 UI 提供层、类型、结果数据。

### `kicad_dfm/child_frame/dfm_child_frame_model.py`

详情窗口列表模型，存储 `[显示文本, 颜色]`：

- 第一列展示问题编号、数值、数量。
- 第二列内部保存颜色。
- `GetAttrByRow()` 根据颜色设置文本颜色。

### `kicad_dfm/child_frame/child_frame_setting.py`

提供远端图层名到 KiCad 当前板图层名的转换，以及单位转换：

- `ChildFrameSetting.layer_conversion()`：处理 `Top Layer`、`Bot Layer`、`Outline`、`InnerN` 等远端图层名。
- `ChildFrameUnitConversion`：提供 mm 到 inch/mil 的转换和列表文案格式化。

### `kicad_dfm/child_frame/diagram_catalog.py`

维护规则图示配置：

- 复用 `picture_catalog.py` 的规则别名，避免图片匹配别名分叉。
- 为每个图示声明语言无关底图文件、标注锚点和说明翻译 key。

### `kicad_dfm/child_frame/diagram_hint.py`

统一加载和渲染规则提示图：

- 优先加载 `kicad_dfm/picture/diagram/<picture_name>.png`。
- 在运行时按标注坐标绘制引线和当前语言说明文本。
- 详情窗口和规则管理窗口共用同一个入口。
- 找不到新图时才进入兼容 fallback；旧语言图片已删除，最终会显示 `none.png`。

### `kicad_dfm/child_frame/picture_match_path.py`

旧图片加载兼容层，根据问题类型和语言后缀匹配历史说明图片。旧 `_zh.png` / `_en.png` 资源已删除，正常运行路径优先使用 `diagram_hint.py`，未命中时显示 `none.png`。

### `kicad_dfm/settings/graphics_setting.py`

远端几何数据和 KiCad 对象之间的匹配层。

职责包括：

- 将远端坐标转换为 KiCad 内部单位。
- 创建临时线段、圆弧、矩形图形。
- 用 `HitTest` 根据坐标匹配走线、过孔、焊盘、图形、铺铜。
- 为不同检查项提供专用匹配方法。

核心常量：

- `ERROR_ACCURACY = 30000`：命中容差。
- `EDGE_WIDTH_EXTEN = 100000`、`LINE_WIDTH_EXTEN = 80000`：部分几何扩展常量。

## 规则和设置

### `kicad_dfm/settings/color_rule.py`

根据规则字符串和实际值判定颜色。

`PcbSetting.get_layer_size()` 根据板框包围盒和边框线宽计算 PCB 尺寸，返回形如 `宽*高` 的字符串。

### `kicad_dfm/settings/single_plugin.py`

维护当前主窗口引用，避免重复打开多个主窗口。

### `kicad_dfm/kicad/swig.py` 中的版本适配

SWIG backend 集中处理 KiCad 版本和能力差异：

- 读取 `pcbnew.GetBuildVersion()`。
- 解析主版本号，并据此声明原生聚焦、原生 DRC marker 等能力。
- 对对象类型、UUID、图层、宽度、可见性、聚焦和 plot API 做跨版本兼容。
- 连接查询、阻焊有效形状和常用对象属性按单次分析缓存；`begin_analysis()` 会在每次运行前失效缓存，防止编辑后的 PCB 复用旧图。
- 几何间距优先使用 KiCad 8+ `SHAPE.GetClearance()`，再用 `Collide()` 校正整数阈值；接口缺失或 SWIG 抛异常时回退到二分碰撞搜索。
