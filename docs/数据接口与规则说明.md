# 数据、接口与规则说明

## B0 基线记录

本仓库在 `assets/` 下随包提供 4 个 `.kicad_pcb` 样例板；跨 KiCad 版本兼容验证脚本仍默认使用本机 KiCad 的 `video` demo 板，并可在原始 demo 被新版 KiCad 改写后从备份中恢复兼容副本：

- 仓库样例板：`assets/video.kicad_pcb`、`assets/flat_hierarchy.kicad_pcb`、`assets/pic_programmer.kicad_pcb`、`assets/amulet_controller_9.kicad_pcb`。
- 主窗口仍保留若干固定路径样例板兜底逻辑，仅用于开发环境。
- 远端兼容缓存：`kicad_dfm/temp.json` 和 `kicad_dfm/name.json` 不随包提供，仅在远端兼容流程运行后按需生成；前者保存分析 JSON，后者记录对应 PCB 名称。
- 最小回归流程：打开插件、执行“快速 DFM 检查”；需要验证制造交付物时，执行“综合 DFM 检查”，确认 Native、Gerber/Drill、合并摘要、详情和定位。

当前 UI 摘要项以 `docs/功能总览.md` 的“摘要检查项”为准，共 21 项：


| 场景 | 方法 | URL | 参数/字段 | 返回字段 |
| --- | --- | --- | --- | --- |
| 区域判断 | GET | `https://ipinfo.io/json` | 无 | `country` |
| 国内上传 | POST multipart | `https://www.eda.cn/openapi/dfm/hqpcb/upfile` | `file=gerber.zip`, `type=kicad`, `Cookie: JSESSIONID=...` | `code`, `data.analyse_id`, `data.kicad_id` |
| 国内轮询 | POST form/query | `https://www.eda.cn/openapi/dfm/hqpcb/getParseResult` | `id`, `kicadid` | `code`, `data.analyse_url` |
| 海外上传 | POST multipart | `https://www.eda.cn/openapi/api/nextpcb/upfile/kiCadUpFile` | `file=gerber.zip`, `region=us`, `type=dfm`, `bcount=10` | `status`, `data.analyse_url` |

当前导出文件基线：

- 输出目录：优先 `<pcb所在目录>/HQDMF/`，失败时退回 `<系统临时目录>/HQDMF/`。
- 压缩包：对 `HQDMF/Gerber_<PCB文件名>` 输出目录执行 ZIP 打包，默认本地文件为 `HQDMF/Gerber_<PCB文件名>.zip`；远端兼容路径上传表单文件名仍可使用 `gerber.zip`。
- Gerber 命名：plot plan 使用 `CuTop`、`CuBottom`、`CuInN`、`EdgeCuts` 等稳定 stem；KiCad 实际文件名可能带板名前缀，例如 `video-CuTop.gbr`，本地检查会按 stem 识别。
- Drill 输出：由 KiCad `EXCELLON_WRITER.CreateDrillandMapFilesSet()` 生成钻孔文件和 map 文件。

## 临时文件

插件会在 `kicad_dfm` 目录下按需读写以下运行时文件；它们不是仓库内置样例：

| 文件 | 写入者 | 用途 |
| --- | --- | --- |
| `temp.json` | `services.remote.download_result()` / `DfmAnalysis.download_file()` | 保存远端 DFM 分析 JSON |
| `name.json` | `guonei_requset_dfm_analysis_file()` / `haiwai_requset_dfm_analysis_file()` | 保存当前分析对应的 PCB 板名 |
| `settings/plugin.log` | `TimeStamp` | 时间戳日志 |

启动主窗口时，`DfmMainframe.add_temp_json()` 会检查 `name.json` 和 `temp.json` 是否存在。如果 `name.json` 中的 `name` 与当前 PCB 文件名去扩展名匹配，或当前名称等于 `*name`，则复用缓存结果。

## 制造文件输出

综合 DFM 检查在制造文件扫描前会生成：

```text
<pcb所在目录>/HQDMF/
```

如果该目录无法创建，则退回：

```text
<系统临时目录>/HQDMF/
```

`services.export.export_fabrication_package()` 每次只清理 `HQDMF/Gerber_<PCB文件名>` 子目录，然后生成 Gerber 文件、钻孔文件和 map 文件。随后 `core.files.zip_directory()` 将该子目录压缩为 `HQDMF/Gerber_<PCB文件名>.zip`。Gerber 本地 DFM 会直接检查这个目录和 ZIP，不上传。

目标结构：

```text
project/
  board.kicad_pcb
  HQDMF/
    Gerber_board/
      board-CuTop.gbr
      board-CuBottom.gbr
      board-CuIn1.gbr
      board-EdgeCuts.gbr
      *.drl
      *map*
    Gerber_board.zip
```

实际文件名允许 KiCad 增加板名前缀，例如 `board-CuTop.gbr` 或 `board_EdgeCuts.gbr`。检查逻辑按稳定 stem 匹配。

## Gerber 本地检查

`services.export_checks.analyze_export_with_results()` 只消费 `ExportResult` 和当前规则组，不重新导出、不访问网络、不依赖 KiCad。默认返回 `issues, summary, native_results`；传入 `include_profile=True` 时额外返回扫描 profile，用于 debug 和性能验证。

## 分析模式和来源契约

| 模式 | 生产者 | 主要字段 | 用途 |
| --- | --- | --- | --- |
| `kicad_native` | `OfflineDfmAnalysis` | PCB UUID、网络、KiCad 精确几何 | 快速检查与综合 Native 来源 |
| `gerber_strict` | `ExportChecks` | 文件、aperture/tool、坐标和制造几何 | 保留不可变制造证据，不直接覆盖设计语义 |
| `gerber_enriched` | `GerberResultObjectMapper` | strict 测量 + UUID/网络映射 | 综合检查中的 Gerber 最终判定 |
| `combined` | `CombinedAnalysisService` | 稳定键合并结果和完整来源观测 | 综合检查最终 UI/报告契约 |

统一 contract 显式记录 `execution_status`、`checked_count`、`violation_count`、`displayed_count`、按类目 findings 和来源计数。finding 身份不包含颜色和测量值：同一物理对象在 Native/Gerber 中出现轻微数值差异时仍可合并，并分别保存在 observation/source view 中。若 Gerber enriched 阶段证明 strict 疑似项属于合法 NetTie 等局部结构，该 strict-only finding 只留在来源视图，不进入综合 verdict。

## 分析结果缓存

`services.analysis_cache` 保存 KiCad 本地、Gerber 本地或综合分析的完整结果，包括 `analysis_result`、`kicad_result`、问题列表、摘要、分析契约和来源视图：

- 首选路径为 PCB 同目录下的 `HQDMF/analysis-cache-v23/<PCB名>.<分析模式>.<输入摘要>.<规则摘要>.json`；目录不可写时回退到系统临时目录的 `HQDFM/analysis-cache-v23/<PCB路径哈希>...json`。
- 缓存绑定规范化 PCB 绝对路径、文件大小、纳秒修改时间、规则组、界面语言和缓存契约版本，避免同名 PCB、中英文或旧算法结果串用。
- 打开主窗口时在首次绘制之后由后台线程加载最新有效缓存；优先恢复综合结果，综合输入失效或不存在时继续查找 Gerber/KiCad 本地结果。PCB 文件、相关制造文件、规则组、语言或缓存版本变化时忽略对应旧缓存。
- 未变化的输入只比较路径、大小和纳秒时间戳，不重新读取并哈希整套 PCB/Gerber 文件；只有文件状态变化时才通过 SHA-256 判断内容是否真的变化。
- 每次手动分析成功后使用临时文件加 `os.replace()` 原子覆盖，避免中途中断留下半写 JSON。
- 单个完整缓存最大 128 MiB，且编码前最多遍历 100 万树节点。复杂 Combined 结果超过任一限制时会跳过该模式缓存，避免为必然超限的数百 MiB 结果继续深遍历；当前分析结果仍正常展示，并可回退到同次保存的 Native 缓存。
- 用户停止检查或分析失败时不写入不完整缓存。
- 缓存中的 `DfmIssue`、`DfmSummary` 和 `Location` 会在加载时恢复为原结果对象，详情定位仍使用已保存的 UUID、图层和几何字段。

交付完整性问题只进入 `Gerber Export`：

| 检查 | 严重级别 | 说明 |
| --- | --- | --- |
| Wrong Output Directory | warning | 输出目录不是预期 `HQDMF` 或使用了 fallback |
| Empty Export Directory | error | 导出目录无文件 |
| Missing Layer File | error | plot plan 中的计划层文件缺失 |
| Empty Layer File | error | 计划层文件为空 |
| Missing Board Outline | error | `EdgeCuts` 或带前缀等价文件缺失或为空 |
| Missing Drill File | error | 无 `.drl` 或等价钻孔文件 |
| Missing Drill Map | warning | 无 map/rpt/map-like 文件 |
| Copper Layer Count Mismatch | error | 计划铜层数和实际非空铜 Gerber 数不一致 |

ZIP 检查只读 central directory，不解压：

| 检查 | 严重级别 | 说明 |
| --- | --- | --- |
| ZIP 不存在或为空 | error | `zip_path` 缺失或 size 为 0 |
| ZIP 无法读取 | error | `BadZipFile` 或无条目 |
| 不安全路径 | error | 绝对路径或 `..` |
| 空条目 | error | 非目录条目 `file_size <= 0` |
| 缺导出文件 | error | `ExportResult.files` 中实际文件未进入 ZIP |

Gerber 文本扫描按命令处理，入口为 `parse_gerber_scan()`：

- 命令流：支持一行内多个 `*` 命令、`%...*%` 扩展命令、注释和属性忽略。
- 单位和坐标：支持 `%MOMM/%MOIN`、`G70/G71`、`%FS`、前/后导零抑制、绝对/增量坐标、大小写命令和常见内部空格。
- 光圈：支持标准圆形、矩形、椭圆、正多边形光圈；支持圆/矩形孔。
- 宏光圈：支持参数替换、变量赋值和基础算术表达式；支持 circle、outline、polygon、vector line、center line、lower-left line、thermal 等常见 primitive。
- 图形：支持 D01/D02/D03、`G01/G02/G03`、`G36/G37` region、`G74/G75` 圆弧象限模式、`G54Dnn` aperture select。
- 极性和重复：支持 `%LPD/%LPC` dark/clear polarity，以及 `%SR` step repeat。
- 铜层 draw aperture 宽度映射为 `Smallest Trace Width`。
- EdgeCuts 是否存在 draw 命令；端点开口大于 `0.05mm` 时映射到 `Copper-to-Board Edge`。

Gerber primitive 跨文件扫描由 `export_scanners.py` 处理：

- 同铜层 primitive 按对象组合映射：`Trace Spacing`、`Trace-to-Pad Spacing`、`Pad-to-Pad Spacing` 归入 `Smallest Trace Spacing`，`SMD Pad Spacing` 独立归入 `SMD Spacing`。全部按铜外形边缘到边缘计算，不使用中心距。`Trace Spacing` 仅接受两个真实走线 segment，`Trace-to-Pad Spacing` 仅接受真实走线 segment 与 pad，任何 zone/region 组合均不归入间距子项。异网同类对象重叠按 `0 mm` 错误报告，规则阈值内的错误和警告全部保留，不再只保留每个子项的单一最小值。
- Gerber 定位会应用 PCB 辅助原点和 Y 轴转换，并优先使用 X2 的元件、焊盘、网络属性映射到原始 KiCad 对象；region 不再按整板中心线误匹配走线。
- Gerber pad 的外形较短一边映射到 `Pad size`；不从该尺寸扣除 Excellon 钻孔。
- 圆孔与圆 pad 的孔环映射到 `RingHole`，X2 `ViaPad` 映射为 `Via Annular Ring`；规则第三档范围内的同值孔环按数值和层分组，但保留组内全部可定位对象。
- 仅当目标铜对象是 SMD pad 时，孔重叠才映射到 `Holes on SMD Pads`；孔源按 Via/BGA Via、NPTH、PTH 分类。
- 镀孔 PTH/Via 只与真实走线 primitive 配对并映射到对应外/内层 `*-to-Trace` 子项；明确排除 pad flash 和 zone/region。NPTH 与所有铜层上的走线、pad、铺铜计算距离，但每个物理孔只保留全局最小的 `NPTH-to-Copper` 结果，结果层固定为 `Drl`；命中的铜层保存在 related 几何证据中用于定位。
- 铜 primitive 到 EdgeCuts 中心线的外形边缘距离映射到 `Copper-to-Board Edge`。异形板框的直线、圆弧、凹边和内轮廓全部参与最近距离计算；圆弧按最大 0.001 mm 弦高误差自适应细分，并用空间索引证明最近边，不使用板框外接矩形。轮廓闭合检查会在 0.05 mm 容差内合并 Gerber 舍入端点并检查所有节点，不再因某一对端点接近而误判整体闭合。
- `SMD-to-Board Edge` 仅接受真实 SMD pad，`Trace-to-Board Edge` 仅接受非 flash 的 `Conductor` 走线，`ViaPad`、带钻 PTH pad 和 region 铜皮进入通用 `Copper-to-Board Edge`。Gerber 将长圆/圆角矩形焊盘拆成多个 primitive 时，按 X2 object/flash 和连通关系还原逻辑焊盘：任一成员匹配钻孔或槽孔即将整个焊盘排除出 SMD；SMD、PTH 和其他复合焊盘均按一个逻辑对象输出最小板边间距，避免碎片重复。每条结果同时保存命中的真实 EdgeCuts 线段用于复核。
- Excellon 圆孔和槽孔的孔壁到 EdgeCuts 最近距离映射到 `Hole-to-Board Edge`。圆孔按圆心距减半径，G85/铣槽按中心线段到板边的精确距离减刀径半径，不使用孔或板框外接矩形。纯制造文件根据 plating 与 `ViaDrill` 分类为 PTH、Via 或 NPTH；螺丝孔用途无法仅凭孔径可靠推断，只有综合分析回映到 PCB 的 mounting/screw footprint 后才改归 `Screw Hole-to-Board Edge`。
- 只有孔形状明确包含直角时才映射到 `Special Drill Holes / Square/Rectangular Drills`；KiCad 标准长圆钻孔及 Excellon G85/铣槽具有圆弧端部，不按正/长方形孔报告。孔与 EdgeCuts 相交映射到 `Special Drill Holes / Castellated Holes`；该类别只包含这两个子项。
- 外层 SMD pad 缺少阻焊开窗属性，或外层铜区未匹配同侧 F/B.Mask 开窗时，映射到 `Missing SMask Openings`；正常 pad 开窗不报错。
- F/B.Mask 开窗之间的阻焊桥、开窗与走线关系、单个开窗覆盖多个网络分别映射到 `Solder Mask Analysis` 的三个子项。
- X2 同网络铜对象的断开分量、悬空端点、未连接 ViaPad 映射到 `Signal Integrity`。

Excellon 文本扫描逐行处理：

- 单位 header：`METRIC` / `INCH`。
- tool 定义：`TnnCdiameter`。
- drill 坐标。
- slot 命令。
- 可解析坐标的最小孔距。

性能约束：

- 导出后只遍历一次生成 `ExportResult.files`。
- 完整性检查只读文件元数据。
- Gerber/Drill 禁止一次性 `read()` 整文件；Gerber 命令流由 `iter_gerber_commands()` 增量切分。
- 同一 Gerber 文件内相同 draw aperture 宽度只产生一条最小线宽候选。
- 铜间距、逐孔孔到铜、阻焊和铜到板边距离使用 primitive bbox 预筛与安全剪枝；每个适用钻孔分别保留最近候选，避免只返回全局单一结果。
- 扫描类违规结果不设数量上限；每个满足红色/黄色阈值的对象或对象对都必须进入结果。黑色正常明细可按规则子项聚合为极值，但这不会影响违规检查和统计。

## 外部接口

以下接口仅用于远端兼容路径，不是当前 Gerber DFM 入口的依赖。

### 区域判断接口

主窗口启动后后台请求：

```text
GET https://ipinfo.io/json
```

读取返回 JSON 的 `country` 字段：

- `CN`、`HK`：使用国内 DFM 接口。
- 其他或获取失败：使用海外 DFM 接口。

### 国内上传接口

```text
POST https://www.eda.cn/openapi/dfm/hqpcb/upfile
```

请求：

- multipart file 字段：`file=("gerber.zip", <zip>, "application/zip")`
- form data：`type=kicad`
- header：源码中固定传入 `Cookie: JSESSIONID=...`

期望响应：

```json
{
  "code": 2000,
  "data": {
    "analyse_id": "...",
    "kicad_id": "..."
  }
}
```

随后轮询：

```text
POST https://www.eda.cn/openapi/dfm/hqpcb/getParseResult?id=<analyse_id>&kicadid=<kicad_id>
```

成功后从 `data.analyse_url` 下载 JSON。

### 海外上传接口

```text
POST https://www.eda.cn/openapi/api/nextpcb/upfile/kiCadUpFile
```

请求：

- multipart file 字段：`file=("gerber.zip", <zip>, "application/zip")`
- form data：
  - `region=us`
  - `type=dfm`
  - `bcount=10`

期望响应中包含：

```json
{
  "status": true,
  "data": {
    "analyse_url": "...?id=<id>&kicadid=<kicadid>"
  }
}
```

源码用正则从 `analyse_url` 提取 `id` 和 `kicadid`，随后轮询：

```text
GET https://www.eda.cn/openapi/api/nextpcb/DfmView/getParseResult?id=<id>&kicadid=<kicadid>
```

成功后从 `data.analyse_url` 下载 JSON。

## 远端 JSON 检查项和 Gerber 本地映射

`analysis_json()` 固定读取这些键：

| 键 | 说明 |
| --- | --- |
| `Signal Integrity` | 电气信号类问题，如断头线、孤立铜、无效过孔、锐角等 |
| `Smallest Trace Width` | 最小线宽规则来源，本地会重新遍历走线 |
| `Smallest Trace Spacing` | 最小线间距 |
| `SMD Spacing` | 独立的 SMD 焊盘间距，默认三档 6/8/10 mil |
| `Pad size` | 焊盘尺寸规则来源，本地会重新遍历焊盘 |
| `Hole Size` | 钻孔孔径 |
| `RingHole` | 孔环规则来源，本地会重新检查过孔/PTH |
| `Drill Hole Spacing` | 孔到孔 |
| `Drill to Copper` | 孔到铜 |
| `Copper-to-Board Edge` | 铜到板边 |
| `Hole-to-Board Edge` | 孔到板边 |
| `Special Drill Holes` | 特殊孔 |
| `Holes on SMD Pads` | SMD 焊盘上孔 |
| `Missing SMask Openings` | 阻焊少开窗 |
| `Solder Mask Analysis` | 阻焊桥、阻焊盖线、阻焊覆盖多个网络 |
| `Drill Hole Density` | 本地按钻孔数/板框有效面积计算；中文 `display` 使用“万/m²” |
| `Surface Finish Area` | 本地计算两面阻焊开窗内铜面积占单面板有效面积的百分比 |
| `Test Point Count` | 本地统计有网络且外层可接触的焊盘及未盖油过孔数量 |
| `Gerber Export` | Gerber 本地交付完整性问题，如缺文件、ZIP 异常、铜层数量不匹配 |

Gerber/Drill 本地扫描会尽量合并到既有检查项：

| Gerber/Drill 数据 | 目标检查项 |
| --- | --- |
| 铜层 draw aperture 宽度 | `Smallest Trace Width / Smallest Trace Width` |
| 同层真实 trace/trace、trace/pad 间距 | `Smallest Trace Spacing / Trace Spacing`、`Trace-to-Pad Spacing`；不把 zone/region 当作 trace |
| 同层 pad/pad 通用间距 | `Smallest Trace Spacing / Pad-to-Pad Spacing` |
| 同层非 BGA 的 SMD/SMD 间距 | `SMD Spacing / SMD Pad Spacing` |
| Gerber pad 外形较短一边 | `Pad size / Short Pads`、`Long Pads`；不扣除钻孔 |
| Gerber 圆 pad 与 Excellon 圆孔孔环 | `RingHole / Via Annular Ring`、`PTH Annular Ring` |
| Excellon tool 直径 | `ViaDrill` 进入 `Hole Size / Smallest Drill Size`（最小Via），`ComponentDrill` 进入 `Smallest PTH`（最小插件孔）；二者不会互相混入，NPTH 不进入这两个最小值项目 |
| slot 宽度、外形总长和比例 | `Hole Size / Smallest Slot Width`、`Largest Slot Width`、`Largest Slot Length`、`Slot Aspect Ratio`；槽宽按 KiCad 非圆钻孔短轴或 Excellon 铣刀直径计算 |
| 钻孔边到边间距 | `Drill Hole Spacing` 对应 via/PTH/盲埋孔子项；有网络信息时不混用同网和异网规则 |
| 镀孔 PTH/Via 到真实走线距离 | `Drill to Copper / PTH-to-Trace [Outer/Inner]`、`Via-to-Trace [Outer/Inner]`；不含 pad/zone |
| NPTH 到走线、pad、铺铜距离 | `Drill to Copper / NPTH-to-Copper`；全部铜层参与计算，每孔仅一条全局最小结果并归入 `Drl` |
| Via/BGA Via、NPTH、PTH 与 SMD pad 重叠 | `Holes on SMD Pads` 下对应的四个子项 |
| 铜层直线到 EdgeCuts 距离 | `Copper-to-Board Edge / Trace-to-Board Edge` |
| Gerber flash pad 到 EdgeCuts 距离 | `SMD-to-Board Edge` 仅限 SMD；Via/PTH flash（包括拆分为多个 primitive 的复合通孔焊盘）映射到通用 `Copper-to-Board Edge`；每个逻辑焊盘仅输出一条最小板边间距结果 |
| Excellon 圆孔/槽孔到 EdgeCuts 距离 | `Hole-to-Board Edge / PTH-to-Board Edge`、`Via-to-Board Edge`、`NPTH-to-Board Edge`；综合回映 mounting/screw footprint 后可改归 `Screw Hole-to-Board Edge` |
| EdgeCuts 开口 | `Copper-to-Board Edge / Trace-to-Board Edge` |
| Gerber FS 缺失 | `Signal Integrity / Trace Mssing` |
| Excellon 单位、工具、命令结构异常 | `Gerber Export`；不再伪装为孔形状异常 |
| SMD pad 缺少同侧阻焊开窗 | `Missing SMask Openings / Missing SMask Opening` |
| F/B.Mask 开窗几何与网络关系 | `Solder Mask Analysis / Solder Mask Bridge`、`Solder Mask Covers Trace`、`Solder Mask Covers Multiple Nets` |

交付完整性错误不随规则组降级；制造能力结果使用当前 profile 的 `RULE_CATALOG` / `ColorRule` 判色。三档规则组只缩放允许随制造能力分档变化的尺寸类规则；`Pad size`、`Drill to Copper`、`Solder Mask Analysis` 等明确固定的制造规则，以及布尔类、拓扑缺陷类、结构上限类、比例范围类和 SMD 焊盘上孔重叠类规则保持目录值，避免把同一缺陷解释成不同几何含义。

可缩放尺寸类规则的默认语义为：

| 规则组 | profile id | min 类阈值 | max 类阈值 |
| --- | --- | --- | --- |
| Basic | `economy` | 基准值 `* 1.25` | 基准值 `/ 1.25` |
| Standard | `standard` | 基准值 | 基准值 |
| Advanced | `precision` | 基准值 `* 0.8` | 基准值 `/ 0.8` |

## 插件内部结果结构

大多数检查项会被归一化为：

```json
{
  "display": "摘要显示值",
  "display_inch": "英制摘要显示值",
  "color": "red|gold|black",
  "check": [
    {
      "result": [
        {
          "item": "子项名称",
          "rule": "规则字符串",
          "layer": ["图层名"],
          "value": "测量值",
          "type": 0,
          "color": "red|gold|black",
          "sx": "起点 x",
          "sy": "起点 y",
          "ex": "终点 x",
          "ey": "终点 y"
        }
      ]
    }
  ]
}
```

字段说明：

- `item`：问题子类型，例如 `Trace Spacing`、`PTH Annular Ring`。
- `rule`：远端规则字符串，逗号分隔。
- `layer`：远端图层名或 KiCad 图层名。
- `value`：实际测量值，通常为 mm。
- `type`：几何类型。
- `color`：按规则判定的结果颜色。
- `sx/sy/ex/ey/cx/cy`：远端坐标或 Gerber/Drill 文件坐标，解析后用于 KiCad 定位。
- `item_type`：本地对象类型；Gerber/Drill 文件结果分别使用 `gerber`、`drill`。
- `raw`：保留来源文件、tool、aperture、segment、point、bbox、width、diameter 等定位和排查元数据。

## 几何类型

远端 JSON 由 `core/dfm_json.py` 归一化为兼容结果结构，主要处理三类结果：

| type | 含义 | 定位方式 |
| --- | --- | --- |
| `0` | 几何结果列表，内部通过 `et` 细分线段/圆弧/点矩形 | 匹配 KiCad 对象或创建临时图形 |
| `2` | 单条线段结果 | 创建或匹配线段 |
| 其他 | 信号完整性等复合区域结果 | 保存 `result` 数组，常以矩形/区域处理 |

`type=0` 下的 `et`：

- `et=0`：线段，使用起点/终点。
- `et=1`：圆弧，使用起点/终点/圆心。
- 其他值：点或矩形中心，使用中心点。

## 坐标和图层转换

远端坐标和 Gerber/Drill 文件坐标按 mm 处理。定位时，插件读取 KiCad Aux Origin：

```text
KiCadX = Decimal(remoteX) * 1000000 + AuxOrigin.x
KiCadY = AuxOrigin.y - Decimal(remoteY) * 1000000
```

图层转换由 `ChildFrameSetting.layer_conversion()` 处理：

| 远端图层名 | KiCad 图层 |
| --- | --- |
| `Top Layer` | `board.GetLayerName(0)` |
| `Top Solder` | `board.GetLayerName(1)` |
| `Bot Layer` | `board.GetLayerName(2)` |
| `Bot Solder` | `board.GetLayerName(3)` |
| `Top Silk` | `board.GetLayerName(5)` |
| `Bot Silk` | `board.GetLayerName(7)` |
| `Outline` | `board.GetLayerName(25)` |
| `Bot Paste` | `board.GetLayerName(33)` |
| `Top Paste` | `board.GetLayerName(35)` |
| `InnerN` | 根据 KiCad 内层编号映射 |

对本地分析项 `Pad size`、`Smallest Trace Width`、`RingHole`、`Missing SMask Openings`、`Solder Mask Analysis`，图层列表通常已是 KiCad 图层名，不再转换。

Gerber 文件层名会转换为 KiCad 图层名：

| Gerber stem | KiCad 图层 |
| --- | --- |
| `CuTop` 或 `*-CuTop` | `F.Cu` |
| `CuBottom` 或 `*-CuBottom` | `B.Cu` |
| `CuInN` 或 `*-CuInN` | `InN.Cu` |
| `EdgeCuts` 或 `*-EdgeCuts` | `Edge.Cuts` |

## 规则字符串和颜色判定

远端规则字符串通过逗号拆分。当前代码主要使用：

```text
rule1,rule2,rule3,rule4,...
```

颜色判定逻辑：

1. 如果规则不存在，部分本地分析默认返回 `red`。
2. 如果 `rule1 < rule2`：
   - `value < rule1`：`red`
   - `rule1 < value < rule2`：`gold`
   - 其他：`black`
3. 如果 `rule1 >= rule2`：
   - `value > rule1`：`red`
   - `rule2 < value < rule1`：`gold`
   - 其他：`black`

远端结果颜色归一化还会处理：

- 如果规则第一段或第二段为 `-`，直接标为 `red`。
- 如果第四段为 `1`，支持百分比规则，将百分号转成小数再比较。
- 聚合颜色时，只要任一问题为 `red`，项目为 `red`；否则只要任一问题为 `gold`，项目为 `gold`；否则为 `black`。

## 本地分析结果差异

快速与综合检查的结果差异是契约设计的一部分：快速只发布 `kicad_native`；综合同时保留 strict/enriched 来源，并以 Native + enriched 形成 verdict。综合结果不是简单相加：相同 finding 会去重，来源测量会保留；文件交付错误和绘制后的制造几何差异只存在于综合结果。

本地分析项会保留 KiCad 对象 UUID：

```json
{
  "id": "<KiCad item UUID>",
  "layer": ["F.Cu"],
  "value": "0.12",
  "item": "Smallest Trace Width",
  "color": "red"
}
```

详情窗口定位这些项时，直接调用：

```python
item = board.ResolveItem(result["id"])
item.SetBrightened()
pcbnew.FocusOnItem(item, board.GetLayerID(item.GetLayer()))
```

因此本地分析项通常比纯远端坐标结果更容易精确定位。

Gerber/Drill 文件结果没有 KiCad UUID，但可在有坐标时通过临时图形定位：

```json
{
  "item_type": "gerber",
  "layer": ["F.Cu"],
  "value": "0.135",
  "item": "Smallest Trace Width",
  "color": "gold",
  "type": 0,
  "et": 0,
  "sx": "1.000000",
  "sy": "0.250000",
  "ex": "9.000000",
  "ey": "0.250000",
  "raw": {
    "file": ".../Gerber_video/video-CuTop.gbr",
    "width": 0.135
  }
}
```

文件坐标归一化规则：

1. `raw.segment` 存在时直接转换为 `sx/sy/ex/ey`。
2. `raw.point` 存在时，使用 `raw.width` 或 `raw.diameter` 生成一条短线段，并额外保留 `cx/cy`。
3. `raw.bbox` 存在时，取 bbox 长轴方向的中心线段作为定位高亮。
4. 没有上述字段时，详情窗口只展示文本，不创建 Gerber/Drill 临时图形。

缺文件、空文件、ZIP 异常等 `Gerber Export` 问题没有 PCB 对象位置，详情窗口只展示信息，不隐藏全部图层。

## 单位显示

主窗口和规则窗口根据 `pcbnew.GetUserUnits()` 转换：

- `0`：inch。
- `5`：mil/mils。
- 其他：mm。

转换关系：

```text
inch = mm / 25.4
mil = mm * (1000 / 25.4)
```

内部长度测量值统一保留到小数点后 6 位 mm，再进行规则判级和单位换算；界面最终显示时按所选单位保留 3 位小数。这样可覆盖 KiCad 的 1 nm 内部坐标精度，并避免 3 mil（0.0762 mm）等尺寸因提前取整显示为 2.992 mil。`Aspect Ratio`（板厚/PTH 孔径，即孔厚径比）和 `Slot Aspect Ratio` 是无量纲比值，不参与 mm/inch/mil 换算。

详情窗口也使用相同的精确换算关系，但部分显示字符串使用 `mil`，部分使用 `mils`，这是当前源码行为。

## 当前实现边界

- Gerber 导出会按板级铜层数生成 F.Cu、可用的 InN.Cu 和 B.Cu plot plan；具体上限取决于当前 KiCad 运行时提供的层常量。
- `Missing SMask Openings` 按 SMD pad 的阻焊属性判断，并匹配外层铜区与同侧 F/B.Mask 开窗；`assets/pic_programmer.kicad_pcb` 的正常 pad 开窗不产生误报。
- `Solder Mask Analysis` 已实现阻焊桥、阻焊盖线和阻焊覆盖多个网络；多网络子项依赖可靠网络属性，缺失时不猜测。
- Gerber/Excellon 通常不包含完整盲埋孔层跨和 BGA footprint 类型；这些专项以 KiCad 对象分析为准。板厚可从 PCB 取得时，Excellon PTH 仍可计算 `Aspect Ratio`。
- `Drill Hole Density`、`Surface Finish Area` 和 `Test Point Count` 均直接显示本地统计值；详情按钮展示同一数值，不生成规则违规明细。
- 远端接口错误大多以弹窗提示，部分请求异常后没有统一返回值兜底。
- `analysis_json()` 只读取远端 JSON 并委托 `core/dfm_json.py` 归一化，不再写出调试用 `output.json`。
- 规则类目和分析子项使用稳定英文键，中文界面通过 gettext/语言映射显示；I18N 校验确保目录中的中英文键完整对应。
- 远端兼容路径依赖服务返回结构；当前 KiCad/Gerber 主流程已具备本地离线分析能力。
- 综合结果的完整来源视图可能远大于 legacy UI 行集合；超过缓存限制时不会持久化 Combined，启动恢复将回退到有效的 Gerber 或 Native 结果。
- 当前 wx 主流程使用协作式 yield 而非后台线程。纯文件 Gerber 扫描具备未来迁移到 worker 的条件，但 SWIG PCB 对象、保存、导出和 UUID 映射仍应留在 KiCad 安全线程。
