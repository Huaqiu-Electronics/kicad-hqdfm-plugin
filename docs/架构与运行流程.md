# 架构与运行流程

## 总体结构

```text
KiCad pcbnew
  |
  v
plugin.py -> _main.py -> _baseApp.py
  |
  v
DfmMainframe
  |
  +-- DfmMaindailogView       主界面摘要、规则组单选、操作按钮
  +-- OfflineDfmAnalysis      离线 DFM 分析
  +-- LocalChecks             本地 KiCad 对象检查
  +-- ExportChecks            Gerber/Drill 本地分析
  +-- AnalysisProgress        当前阶段、进度与协作式取消
  +-- GerberResultObjectMapper Gerber/Drill 结果 UUID 回映
  +-- DfmAnalysis             在线上传/下载/解析兼容路径
  +-- RuleManagerView         规则查看和编辑
  +-- DfmChildFrame           详情列表、筛选、定位和高亮
  +-- LocateService           KiCad 对象选择、高亮、标记
  +-- FocusService            KiCad 8+ 原生聚焦缩放
```

## 启动流程

1. KiCad 加载插件包后，顶层 `__init__.py` 注册 `kicad_dfm.plugin.Plugin`。
2. `Plugin.Run()` 调用 `_main()`。
3. `_main()` 复用已有主窗口；没有已有窗口时创建 `BaseApp`。
4. `BaseApp` 初始化 gettext `_()`，再创建 `DfmMainframe`。
5. `DfmMainframe` 获取当前 `pcbnew.GetBoard()`，记录可见层/可见元素，初始化摘要表和按钮事件。

## 主界面状态

主界面维护以下关键状态：

- `settings`：从 `core/settings.py` 读写，包含默认规则组、单位、定位和兼容网络参数；分析方式由两个显式按钮选择，不再由隐藏配置决定。
- `control`：中文/英文检查项映射，来自 `config.Language_chinese` 或 `config.Language_english`。
- `gal_set` / `ele_gal_set`：进入插件时的可见层和可见元素，用于关闭窗口时恢复。
- `analysis_result`：远端兼容结果、KiCad 本地结果和 Gerber 本地结果共用的兼容结果结构。
- `kicad_result`：本地 KiCad 检查项结果。
- `json_analysis_map`：主界面摘要表模型数据。
- `analysis_progress`：当前工作内容、完成比例和停止状态；后台检查在类目与耗时循环边界读取取消信号。

## 分析入口与结果模式

当前主窗口有两个显式入口：“快速 DFM 检查”执行 PCB 对象 Native 分析；“综合 DFM 检查”顺序执行 Native、Gerber/Excellon 导出扫描、语义补充和合并。旧 `analysis_mode` 设置已移除，避免按钮行为与隐藏配置互相矛盾。

内部结果契约使用四种稳定模式：

| 模式 | 含义 | 是否直接作为主入口结果 |
| --- | --- | --- |
| `kicad_native` | KiCad PCB 对象检查 | 是，快速检查 |
| `gerber_strict` | 只依据 Gerber/Excellon 制造证据 | 否，作为综合来源视图保留 |
| `gerber_enriched` | strict 结果经 KiCad UUID、网络和 NetTie 语义补充 | 是，综合检查的 Gerber 判定来源 |
| `combined` | Native 与 enriched 的稳定键合并结果 | 是，综合检查最终结果 |

快速流程：

1. `DfmMainframe.run_offline_analysis()` 读取当前规则组。
2. `OfflineDfmAnalysis` 创建兼容结果骨架。
3. `LocalChecks` 遍历当前 PCB，按类目上报当前工作内容和完成比例，并在检查边界响应停止请求。
4. 若用户停止，终止剩余检查，不发布或缓存不完整结果。
5. 主界面刷新摘要，KiCad 6/7 自动同步 UUID-backed 结果到会话临时原生 DRC marker；KiCad 8+ 跳过 native marker。
6. 保存 `kicad_native` 缓存，完成工作流后再显示成功提示。

综合流程：

1. 完整运行快速流程的 Native 分析，但暂不发布最终 UI。
2. 保存当前 PCB，导出 Gerber/Drill 到 `HQDMF/Gerber_<PCB文件名>`，并生成 `Gerber_<PCB文件名>.zip`。
3. `services.export_checks.analyze_export_with_results()` 检查导出完整性和 ZIP 元数据。
4. `export_parsers.parse_gerber_scan()` / `parse_excellon_scan()` 解析文件，生成 `GerberScan` / `ExcellonScan`。
5. `export_scanners.py` 在 Gerber/Drill primitive 上计算线宽、间距、孔径、孔环、孔到铜、阻焊和铜到板边等制造能力结果，形成 `gerber_strict` 来源视图。
6. 整次 Gerber 阶段复用一个 `GerberResultObjectMapper`，对文件侧结果尝试高置信 UUID 回映；唯一命中时补全 `id` 并提升为原生对象定位，低置信或多候选时保留文件坐标，形成 `gerber_enriched`。
7. `CombinedAnalysisService` 以稳定 finding key 和来源 alias 合并 Native/enriched；重复问题保留来源观测但只发布一项，enriched 已明确抑制的 strict-only 疑似项不进入综合判定。
8. 完整性问题保留在 `Gerber Export` 后台结果中；存在问题时自动弹出文件完整性对话框，主界面只发布制造规则摘要和来源视图。
9. KiCad 6/7 对 UUID-backed 结果自动同步 native DRC marker；纯文件坐标结果保留插件临时图形定位。
10. 先保存较紧凑的 Native 缓存，再尝试保存 Combined 缓存；中途停止或失败时不写入不完整结果。

Gerber 解析当前分为四层：

- `export_gerber_commands.py`：命令切分、单位、坐标格式、插补模式、region、step repeat。
- `export_gerber_apertures.py`：标准光圈、宏光圈、flash primitive。
- `export_gerber_primitives.py`：draw、flash、region 几何落库，生成 `segments`、`primitives`、`clear_masks` 和线宽 finding。
- `export_parsers.py`：扫描状态机，维护 Gerber 文件上下文并调度上述模块。

独立 Gerber-enriched 流程和远端 `DfmAnalysis` 仍作为兼容入口保留，但不占用主窗口的两个产品入口；综合检查不依赖上传、轮询或下载 JSON。

## 当前本地检查

`LocalChecks` 已实现：

- `Signal Integrity`：检查断线、锐角、孤立铜、悬空线端和未连接过孔。
- `Smallest Trace Width`：遍历走线宽度。
- `Smallest Trace Spacing`：检查同层对象间距。
- `SMD Spacing`：独立检查非 BGA 的同层 SMD-SMD 间距，并按声明组、铜层和局部 clearance 限定 NetTie 豁免范围。
- `Pad size`：直接检查焊盘外形较短一边；长宽比大于 1.2 时归入 Long Pads，不扣除钻孔。
- `Hole Size`：检查过孔、PTH、NPTH、槽孔和方形/矩形孔的孔径或外形尺寸，并以板厚/PTH 孔径计算孔厚径比。
- `RingHole`：检查过孔和 PTH 孔环。
- `Drill Hole Spacing`：检查孔边到孔边间距；同网与异网 via 分别使用对应规则，同网 PTH 不误用异网规则。
- `Drill to Copper`：PTH/Via 只检查到同层 trace；NPTH 跨全部铜层检查 trace、pad 和铺铜，但每个物理孔只输出一条 `Drl` 层全局最小结果。
- `Copper-to-Board Edge`：检查走线/焊盘到板边距离。
- `Hole-to-Board Edge`：检查 PTH、Via、螺丝孔、NPTH 的孔壁到板边距离；槽孔按实际长圆孔外形计算。
- `Special Drill Holes`：仅检查正/长方形孔和半孔。
- `Holes on SMD Pads`：目标严格限定为 SMD 焊盘，按 KiCad 有效铜形状检查 Via/BGA Via、NPTH、PTH 的钻孔重叠；不同网络也不会跳过。
- `Missing SMask Openings`：按 pad 阻焊属性检查 SMD 焊盘，并检查外层铜区是否匹配同侧开窗。
- `Solder Mask Analysis`：检查阻焊桥、阻焊盖线和单个阻焊开窗覆盖多个网络。
- `Drill Hole Density`：实际钻孔数除以板框有效面积。
- `Surface Finish Area`：两面阻焊开窗内铜面积占单面板有效面积的比例。
- `Test Point Count`：有网络且可从外层接触的焊盘和未盖油过孔数量。

Gerber 本地分析会补充制造交付物视角的结果，包括 `Signal Integrity`、`Smallest Trace Width`、`Smallest Trace Spacing`、`SMD Spacing`、`Pad size`、`Hole Size`、`RingHole`、`Drill Hole Spacing`、`Drill to Copper`、`Copper-to-Board Edge`、`Hole-to-Board Edge`、`Special Drill Holes`、`Holes on SMD Pads`、`Missing SMask Openings` 和 `Solder Mask Analysis`。跨文件几何类结果依赖 Gerber primitive、阻焊 primitive 与 Excellon 孔位交叉计算。

## 分析进度与停止

- 主窗口在 KiCad 本地分析和 Gerber 导出分析期间显示进度条及当前工作内容，而不是只显示不确定进度动画。
- `core/progress.py` 提供统一进度事件和取消状态；本地类目检查、导出阶段和 Gerber/Excellon 扫描阶段共用该契约。
- `Stop Analysis` 只请求协作式取消，不强制终止 KiCad 进程；当前安全检查点返回后即停止后续工作。
- 已停止、异常退出或结果尚未完整合并的分析不会覆盖最近一次有效缓存。
- 快速检查把 Native 主阶段映射到 0%-90%，UI、marker 和缓存收尾映射到 90%-100%；综合检查按 Native、导出、Gerber 扫描/补充、合并和缓存划分互不重叠区间，禁止进度倒退。
- `LocalChecks` 的循环心跳最多每 50 ms 触发一次 UI yield，在保持停止响应的同时避免高频 `wx.YieldIfNeeded()` 成为热点。

## 性能设计

- KiCad 原生连接图返回完整连通簇时，每个分量只查询一次，不再对簇内每个对象重复搜索。
- KiCad 8+ 几何优先调用 `SHAPE.GetClearance()` 获取直接距离，并以 `Collide()` 校正 1 nm 阈值；不支持或 SWIG 抛异常时回退到二分碰撞搜索。
- Gerber UUID 回映在整次检查中复用候选、bbox、layer 和 X2 pad 索引。
- Combined 只对来源视图做一次必要的独立快照，不重复规范化完整结果树。
- 缓存预检同时限制 128 MiB 编码体积和 100 万树节点；超大 Combined 结果会跳过持久化并保留 Native 回退缓存。
- 当前分析仍在 wx 事件线程上协作式运行；文件扫描通过进度 yield 保持可停止。把 SWIG PCB 对象访问整体迁移到后台线程不安全，后续如并行化，应只迁移纯文件 Gerber 扫描并通过 `wx.CallAfter` 发布结果。

## 规则生效流程

主界面规则组使用 RadioButton 列表，当前可选：

- `Basic`
- `Standard`
- `Advanced`

规则读取优先级：

1. 主界面当前选中的规则组。
2. 分析结果中已有规则。
3. 内置默认规则目录。

切换规则组后，如果当前已有分析结果，主界面会立即重新计算本地检查项并刷新摘要。分析缓存同时绑定 PCB 文件状态、规则组、语言和缓存契约版本，避免中英文结果或旧算法结果交叉复用。

Gerber DFM 结果不复用旧颜色；需要按当前规则组重新导出/分析，或由后续缓存测量值后重新判色。

规则编辑流程：

1. 打开 `RuleManagerView`。
2. 选择一条规则。
3. 下方输入框自动聚焦并全选当前值。
4. 规则类目、分析项和分析子项均通过稳定英文键映射到当前语言；右侧显示对应语言的规则说明图。
5. 输入框内容实时写回表格行。
6. 保存时校验三段规则值并写入 `settings/rule_profiles.json`。

## 可见层控制

详情定位可能临时隐藏无关层。Gerber/Drill 文件坐标结果定位时不会隐藏全部图层，避免看不到临时高亮。插件提供两处恢复：

- 主窗口 `Reset Layers` 按钮：显示全部 PCB 层和可见元素。
- 主窗口关闭时：恢复进入插件时记录的可见层和可见元素。

显示全部逻辑调用 `SwigBackend.set_visible_alls()`，优先使用 KiCad `SetVisibleAlls()`，并补充设置 `SetVisibleLayers()` / `SetVisibleElements()`，保证 KiCad 6.0-10.0 行为一致。

## 定位和高亮

本地检查项使用 KiCad 对象 UUID 定位：

1. `SwigBackend.item_id()` 获取稳定 UUID。
2. `SwigBackend.resolve_item()` 用缓存 UUID 映射解析对象。
3. `DfmChildFrame.analysis_process()` 每次选择一条明细时先清理上一次选择和临时图形，再进入延迟缩放模式。
4. `LocateService` 选择、加亮 PCB 对象，并只保留贴近问题对象的可编辑目标标记；track 类对象同时保留精确线段和外围目标框，避免细线问题定位后仍难以发现。
5. 中间定位分支只记录最后一个缩放范围，不立即反复调用 KiCad 视图 API。
6. 图层隐藏、Gerber/Drill 临时图形和目标标记全部处理完成后，`LocateService.flush_focus()` 只请求一次最终聚焦；KiCad 6/7 会保留高亮和标记但不自动缩放。

KiCad API 差异：

- KiCad 8.0+ 的 SWIG `pcbnew` 暴露 `FocusOnItem(item, layer)`，`FocusService` 只调用该原生 API，并在签名不兼容时退到 `FocusOnItem(item)`。
- KiCad 6.0/7.0 的独立 Python API 没有全局 `FocusOnItem`；插件只保留选择、加亮、目标标记和可见层处理，不再通过菜单、快捷键、鼠标滚轮或系统按键模拟缩放。
- 可见层统一通过 `SetVisibleAlls()` / `SetVisibleLayers()` / `SetVisibleElements()` 恢复全部可见，避免目标对象被隐藏。

缩放和编辑契约：

- 缩放框只按坐标即时创建，不能缓存或复用已删除的 SWIG 图形对象。
- 选择过程使用 `begin(defer_focus=True)`，所有中间聚焦请求只记录范围，避免多次 `FocusOnItem` 互相覆盖。
- 最终缩放发生在隐藏无关层之后，保证选择不同条目时每次都以当前结果为准。
- 用于缩放的大范围焦点框在 GUI 中短暂保留后自动删除，给 KiCad 异步视图处理留出时间；下一次定位或关闭窗口也会清理，避免挡住用户编辑。
- PCB 上只保留精确目标标记和实际对象的选中/加亮状态，用户可直接点击或编辑原始 PCB 对象。
- 如果详情行没有命中原始 PCB 对象，但携带坐标、矩形或 bbox，`DfmChildFrame` 会回退绘制坐标目标并缩放到该范围，不能静默无高亮。
- 回归验证使用 `tools/verify_detail_locate_kicad_versions.py`，从 `D:\KiCad\6.0\share\kicad\demos\video` 生成真实离线 DFM 单条结果，并构造 `DfmChildFrame` 调用 `analysis_process()`，覆盖“首条缩放、后续条目继续缩放、目标标记存在、焦点框不泄漏、清理后可继续编辑”的链路。

为避免大结果集卡死：

- 单组最多选择前 200 个对象。
- 单组最多创建前 20 个标记。
- 状态栏提示实际显示数量。

KiCad 9/10 中 `PCB_VIA.GetWidth()` 需要 layer 参数，当前通过 backend helper 统一处理，避免 wx debug alert。

Gerber/Drill 文件结果使用文件坐标定位：

- 有 `sx/sy/ex/ey` 的结果会创建临时线段或短线段，并聚焦到对应位置。
- 原始扫描结果优先携带 `segment`，否则携带 `point`，再否则携带 `bbox`；归一化时依次转换为 `sx/sy/ex/ey`。
- `point` 会结合 `width` 或 `diameter` 生成短线段；`bbox` 会沿长轴生成中心线段，便于在板上看到可定位高亮。
- Gerber/Drill 坐标结果同样走延迟最终缩放：先留下精确线段，再用临时焦点框缩放到该结果范围。
- 线宽、孔径、槽、孔距、铜间距、pad 间距、pad 尺寸、孔环、孔到铜、铜到板边和 EdgeCuts 开口会尽量携带可定位坐标。
- 缺文件、空文件、ZIP 异常等纯交付完整性问题没有 PCB 对象位置，在综合检查结束时通过文件完整性对话框集中展示。

## I18N

运行时 gettext 入口在 `core/i18n.py`。`kicad_dfm/language` 目录仍需保留：

- `locale/`：运行时 `.po/.mo` 翻译资源。
- `constraint.py`、`lang_const.py`：语言常量和维护工具仍会引用。
- `geni18n.py`：历史维护脚本，日常推荐使用 `tools/i18n_extract.py` 和 `tools/i18n_compile.py`。

新增 UI 文案后必须运行：

```powershell
python tools/i18n_compile.py
python tools/verify_i18n.py
```
